指示書Gの報告表で「既に反映済み(偽陽性)」の列を「4」と書いたのは表の**行数**(3個別ボート+新居すぐる2戦をまとめた1行)であり、新居すぐる分を実boutで数えると5件になるため、正しい合計は3(収録漏れ)+5(偽陽性)+2(非プロ、山口怜臣×岡田嵐士の両面計上)+1(要個別確認)=**11件で一致**(データの誤りではなく表記の数え方の違い)。

### 偏りの傾向

取りこぼしは**2017年〜2022年の大会に集中**しており、1993-2016年・2023年以降は0件だった。この期間、メインイベント・NEO BLOOD(新人トーナメント)・一部特殊カードのbout表にのみ`id`属性が付与されるHTMLテンプレートが使われていたとみられる(2023年以降は同種のid付与が見られない=テンプレートが変わったか運用が変わった可能性)。

## 4. 修正方針の判断

### 選択肢の比較

- **A. `extractBoutTables()`本体の修正**: regexを`<table(?: id="[^"]*")?>`に広げ、既存の`class="crdl"`フィルタは変更しない。bout表かどうかの判定基準(何をbout表とみなすか)は一切変えず、単に取りこぼしていたHTML構造にもマッチさせるだけの変更。
- **B. データ直パッチのみ(#428と同じ、regexは変更しない)**: 現在の7件は解消できるが、**nightly batch(`update-org-records.yml`)が次回パンクラスを再フェッチした際、同じ位置に同じバグで再び取りこぼされる**(regex自体は直っていないため)。

### 判断: A(本体修正)+ 現在のデータへの直接追記を併用

修斗Fの場合(`resolveOutcome()`の勝者判定ロジック変更、約1,889件の未検証bout全体に影響しうる)とは性質が異なり、**今回は「bout表を検出できるかどうか」という抽出段階のregexのみの変更**であり、後続の解析ロジック(`parseBoutTable`・勝敗判定・階級判定等)は一切変更していない。全418大会走査により「新たにマッチするようになるのは7件のみ・既存の取得結果には一切影響しない」ことを実測済みのため、副作用範囲は限定的かつ既知(+7件、既存bout・既存slug解決には無変化)と判断し、regex本体を修正した。

**フル再スクレイピングは実施していない**(蓄積された手動slug backfill・denylist等の副作用が未検証のため、指示書Gと同じ理由でリスクを回避)。今回の7件は公式イベントページから実測した値を直接`data/pancraseRecords.json`に追記した。regexの修正自体は、次回以降のnightly batchでこの種のbout表を正しく検出できるようにするための恒久対応。
