# Wikipedia戦績取り込み 設計調査(読み取り専用)

調査対象: `~/立ち技/`(立ち技名鑑パイプライン、[chore/migrate-standup-pipeline](../../mnews-worktrees/standup-pipeline-migration)で移設済み)配下の
`raw/wp_parsed.json`(名簿からのWikipediaリンク一覧)・`coverage_population.json`・`coverage_sample.json`・`coverage_measurement.json`
(いずれも別セッションが2026-08-15に生成、本レポートはその成果物を読んで再利用している)。
本調査では実装・データ書き込みは行っていない。

## 前提の食い違い(先に記載)

依頼時点の前提「ja.wikipedia個別記事624件」「同じ30人サンプルで現状24.3%」は、実測値と一致しない。

- 個別記事の候補は**742件**(名簿の`[[wikilink]]`先、重複除去後)であり624件ではない。624件の根拠になった集計方法は特定できなかった。
- 「同じ30人サンプル」は再現不能。前回(613人母集団・24.3%)のサンプルリスト・母集団リストは`~/立ち技/`内のどこにも残っておらず(別セッションがSOURCES.md・全`*.py`・バックアップディレクトリを検索して未発見と確認済み)、ユーザー了承のもと**509人で母集団を再定義**して測定し直されている。したがって本レポートのB-4の数値は「同じサンプル」ではなく、独立した新規測定値である。

以下、実測値ベースで4項目に回答する。

## 1. 機械的にパースできる件数・表の型

**候補742件 → 記事実在621件(missing 121) → 戦績表あり509件(1件のみ表なし113件)。**

判定はMediaWiki APIで記事本体(wikitext)を実測取得して行った(`[[wikilink]]`構文は未作成ページでも同じ形で書かれるため、リンクの有無だけでは実在を判定できない)。

表の型は実測で**3種類**を確認した。

| 型 | 判定 | 機械パース可否 | 件数(概算) |
|---|---|---|---:|
| ①`{{Fight-cont}}`試合単位列挙 | `{{Fight-start}}`〜`{{Fight-cont\|勝敗マーク\|相手\|決着\|大会\|日付}}`〜`{{Fight-end}}` | 可(行単位で相手・日付・決着を抽出できる) | **509件** |
| ②`{{Kickboxing recordbox\|total=N}}`通算成績のみ | 勝敗数の要約テンプレートのみで試合単位の列挙なし | 不可(合計数しか取れず個別bout照合に使えない) | 113件の一部(内訳未分離、下記参照) |
| ③記事はあるが構造化テーブルなし | プロシー本文のみ、または`{{MedalCompetition}}`等の競技会・メダル実績テーブル(アマチュア/五輪系選手に多い) | 不可 | 113件の一部 |
| (参考)記事自体が存在しない | レッドリンク | 該当なし | 121件 |

②③の内訳は、母集団定義スクリプト(`build_coverage_population.py`)が「Fight-contの有無」だけを判定して421件超のwikitextを保存しておらず未分離だったため、本調査で20件を無作為抽出し実測で補足した(サンプル20件中、記事なし14件・②③該当6件。6件は全て③〈構造化テーブルなし〉で、②〈recordbox要約のみ〉の実例は今回のサンプルでは引けなかったが、SOURCES.md記載の第3弾調査で存在自体は確認済み)。②③はどちらも試合単位のデータが取れないため、パース可否の結論(509件のみ可)には影響しない。

## 2. 既存20,238件との重複判定方式

mnews側の現行実装(`scripts/build-kick-data.ts`)は、同一選手内で複数団体に重複掲載された試合を
`date が有れば "date|正規化した相手名"、無ければ "id|bout_id"(=常にユニーク)` というキーで統合している(`dedupe()`)。
**この現行キーをそのままWikipedia由来の行に流用すると、日付nullの既存451件(K-1 245件含む)は
`id|bout_id`で必ずユニーク扱いになるため、Wikipedia側に対応する記録があっても絶対に一致せず、
二重計上される。** これが避けるべき失敗モード。

設計案(優先度順、日付の有無で分岐):

1. **日付が両側にある場合**: 現行と同じ `date|正規化した相手名` で照合。既存の設計を踏襲するだけで足りる。
2. **既存側が日付null(451件)の場合**: 日付では照合できないため、`選手identity + 推定団体(大会名からの正規表現推定、`measure_coverage.py`の`guess_org()`を流用) + 正規化した相手名` を代替キーとする。これで一致すれば「既存資産と同一試合」とみなし、Wikipedia側は**登録せず既存行に出典を追加するだけ**にとどめる(新規行としては追加しない)。
3. 代替キーでも一致しない、または複数候補に割れる(同じ相手と複数回対戦している等)場合は、**自動登録せず保留**にする。二重計上のリスクを取ってでも網羅性を優先する理由がないため、既存パイプライン全体に一貫する「推測しない」方針(`infer_sibling_dates()`の日付補完ロジック等)に合わせる。
4. K-1の245件(原理的に日付が埋まらない)は上記2の対象になるが、K-1公式サイト自体が日付を持たない構造的欠落のため、代替キーでも一致しないケースが最も多く残ると見込まれる。この分は「Wikipedia側にしかない情報」として片側掲載になり得るが、それは二重計上ではなく網羅性の限界として許容する(依頼の要求は「二重計上を起こさない」であって「全件一致させる」ではない)。

## 3. 表示上の出典区別案

現行の選手ページ(`src/app/kick/fighters/[slug]/page.tsx`)には、戦績テーブルの「出典」列に
団体公式サイトへのリンク(`sourceUrl`)と、同じ試合が複数団体に掲載されている場合の
「別出典」リンク(`alsoFrom`)が既にある。読み仮名についても`kanaSource.type`で
出典種別(`published_kana` / `from_romaji`等)を保持し、変換由来かどうかをUIで区別している前例がある(`kick-badge`)。

この2つの既存パターンをそのまま流用する案:

- bout単位に `source_type: 'official' | 'wikipedia'` を持たせ、Wikipedia由来行には既存の`kick-badge`クラスで
  小さな「Wikipedia」バッジを出典リンクの隣に出す(デビュー戦・タイトル種別バッジと同じ並び)。
- 出典リンク自体は引き続き実URLを表示するため、ドメイン(`ja.wikipedia.org`)からも判別はできるが、
  一覧性の観点でバッジを明示した方が「一次資料か二次資料か」が一目でわかる。
- 上記2で「既存行に出典を追加するだけ」にしたケース(公式資料とWikipedia資料が同一試合を指す場合)は、
  `alsoFrom`と同じ仕組みでWikipedia URLを追加し、バッジは出さない(主出典が公式のままのため)。
  バッジは「Wikipediaにしか出典がない行」限定で表示する。

## 4. 30人サンプルでの収録率(新規測定値、24.3%との比較不可)

母集団509人からシード固定(`random.Random(20260815)`)で抽出した30人・全795試合行を対象に測定。

| 指標 | 実測値 |
|---|---:|
| 全体収録率(captured / 対象bout合計) | 13/795 = **1.6%** |
| 個人別収録率の中央値 | 0.0%(0%の人数27/30) |
| A区分(本人ページ自体が対象団体データに無い) | 358件 |
| C区分(本人ページはあるが当該boutだけ無い) | 3件 |
| 追跡15団体のいずれにも該当しない大会(範囲外) | 421件 |

1.6%という値自体は、今回の30人サンプルに魔裟斗・ゲーリー・グッドリッジ等、海外/異種格闘技をまたぐ著名選手が
偶然多く含まれ、Wikipedia記事の戦績表が追跡15団体の範囲を大きく超えて古い/海外の興行を広く収録していることに
起因する(範囲外421件のうち上位は修斗・HERO'S等のMMA系、解散済み別団体、海外団体)。判定ロジックの不具合ではないと
実測ベースで確認済み(団体判定の正規表現漏れは今回の測定過程で5団体分修正済み、修正前後で収録率は1.5%→1.6%とほぼ不変)。

「現状24.3%」は前回の母集団・サンプル定義が不明なため比較の土台が無く、増減を主張できない。

## まとめ

- パース可能な個別記事は509件(候補742件中)、表の型は「試合単位」「通算のみ」「なし」の3種類。
- 重複判定は既存の`date|相手名`キーをそのまま流用すると日付null451件(特にK-1 245件)で二重計上する。
  日付がない場合は選手+推定団体+相手名の代替キーで照合し、一致しなければ自動登録せず保留する設計とする。
- 出典区別は`kick-badge`と`alsoFrom`という既存UIパターンの流用で対応可能、新規の仕組みは不要。
- 収録率は同一条件でのサンプルが失われているため「現状24.3%」との比較はできない。新規測定値は1.6%(30人・795bout中13件)。
