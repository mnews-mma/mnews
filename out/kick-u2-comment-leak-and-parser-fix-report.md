## 2. 本来のU-2スコープ: HTMLコメント内残骸の誤解析、全13ソース測定

### 2-1. 測定方法

全13ソース(module型9: bigbang/deepkick/hoostcup/jka/krossover/njkf/nkb/snka/standup、PROMOS型4: sb/rise/knockout/k1)それぞれについて、builtin `open()`をラップし「`<!-- -->`を除去してから読む」バージョンと「除去しない(通常)」バージョンで独立にbuild()を実行し、自然キー(fighter_slug, event, date, opponent_raw, method_raw, result)で差分を取った(`scripts/standup-pipeline/measure_comment_leak.py`)。

### 2-2. 結果: HoostCupのみで影響あり(他12ソースは影響ゼロ)

| ソース | コメント除去による差分 |
|---|---:|
| **HoostCup** | **あり(下記詳細)** |
| bigbang / deepkick / jka / krossover / njkf / nkb / snka / standup / sb / rise / knockout / k1 | 0件(12ソース全て) |

HoostCupで検出された2つの独立した混入経路:

**経路A: コメントアウトされた重複`<h4>`によるブロック境界のズレ**

`parse_page()`が`<h4>`を単純に全件走査してブロック境界を決めているため、テンプレート移行時にコメントアウトされただけで削除されていない旧形式の`<h4>`が実在の試合として数えられ、ブロック境界が1件分ズレて隣接する試合の決着文が入れ替わる。実例: KINGS NAGOYA11(2022-07-10)の「第12試合」(小川翔 vs テーパプット)の直後にコメントアウトされた旧形式の重複ブロックがあり、この内部に含まれる決着文「判定0-3 (48-50/48-49/47-50)」が、無関係な「第11試合」(実方宏介 vs MAMUTI)・別の試合(剛王 vs 康輝)の行に誤って紐付いていた。

**経路B: コメントアウトされたテンプレート既定値(プレースホルダ)の直接混入**

一部の古いページ(2015年、アマチュア「オープニングファイト」枠)では、決着欄自体がコメントアウトされて出力されておらず(=決着未公開の構造的欠落)、代わりにコメント内に残る無効化済みのテンプレート既定値(「判定　（3-0）」等、複数の異なる試合で同一の値が使い回されているプレースホルダと判明)が、コメントを剥がさない実装のせいで誤って本物の決着文として拾われていた。実例: 清水大輝 vs 矢田喜也、田中恒星 vs 黒田琉樹(いずれも2015-12-27 KINGS NAGOYA)。

### 2-3. 修正

`ingest_hoostcup.py`の`build()`内、raw HTML読み込み直後(全ての抽出処理より前)に`h = re.sub(r'(?s)<!--.*?-->', '', h)`を追加。コメント除去により、経路Aで発生していたブロック境界のズレが解消される副作用として、実方宏介 vs MAMUTIの試合が「マーク(×/○)方式の決着表記」を使う2022年10月以降の新テンプレート(`parse_vs_style()`)側で正しく処理されるようになったが、`parse_vs_style()`自体に「【勝者:Name】形式の明記が無いと勝敗を確定できない」という別の未対応ケースがあり、このままでは行が丸ごと欠落する回帰が生じることが判明した。これに対応するため、`parse_vs_style()`に「名前先頭の○/×マーク(旧テンプレの`class="win"`判定と同じ情報源)から勝敗が一意に確定できる場合はそれを採用する」処理を追加した(△等、一意に確定できないマークの組み合わせは従来通り推測しない)。

### 汎用ゲートの検討と断念

「同一大会内で対戦カードが異なるのに決着文の生テキストが一字一句一致する」という一般的なシグネチャで13ソース横断のゼロ件ゲートを試作したが(`check-kick-duplicate-decision-text-gate.ts`、審判ごとの詳細採点が2組以上明記されている決着文のみを対象にする等、精度を上げても)、実データを調査した結果、判定スコアの完全一致は**独立した別々の試合で偶然発生する頻度が無視できないほど高い**ことが判明した(実例: 泰良拓也選手のHoostCup 2試合〈KINGS KYOTO8 2021-10-17とKINGS NAGOYA11 2022-07-10〉で「判定0-3 (48-50/48-49/47-50)」という完全に同一の3者採点が、無関係な別の対戦カードとして正当に存在する)。ゼロ件ゲートとして運用するには継続的なallowlist維持コストが見合わないと判断し、このアプローチは断念した。代わりに、既存の`check-kick-unknown-result-fallback-gate.ts`(exemption解除により本来の検知能力が有効化された)を、本バグクラスに対する恒久ゲートとして採用する。
