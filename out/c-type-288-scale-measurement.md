# C型288件の規模測定

read-only調査。`data/`・`src/`への変更なし。修正はしていない。

## 前提・出典

[#349](https://github.com/mnews-mma/mnews/pull/349)(指示書R-5、A/B/C型悉皆調査)と
[#353](https://github.com/mnews-mma/mnews/pull/353)(A型2件+C型13件の訂正)の続き。
`out/fighter-records-abc-audit.py`(#349の調査スクリプト)をゼロから再実装せず、
mainブランチ最新時点(`85b3afc`、修斗プロフィール由来bout投入 #350 マージ後)に対して
再実行し、その出力(`out/fighter-records-abc-audit-c-type.csv`)を本調査の入力とした。

### 母数の実測値が288件と一致しないことについて

再実行の結果、C型の総数は**314件**(#349時点の327件から#353で13件が訂正された後、
さらに #350(修斗プロフィール由来bout投入・fighters.ts新規10名追加)等の後続変更を
経て変動した現在値)。288件という数字は #353 の本文中で「大会自体が存在しない」
サブグループ(#349の内訳でいう291件相当)を指して使われた、ある時点のスナップショット
値であり、その後のmainの変更を反映していない。指示書の「C型288件」は本調査の対象
スコープを指し示す名称として扱い、実際の分母は**再実行時点の実測値**を正とした。

## a) 誤検知の除去(対戦相手名クロス突合)

### 手法

先行調査(36件に対して行った手法、修斗⇔SHOOTO・闘裸男⇔TORAO・北海道⇔Hokkaido等の
表記ゆれで61%が誤検知だった調査)と同じ考え方を踏襲: 大会名の一致ではなく、
**対戦相手名の一致**でboutの実在を確認する。C型は「大会名の一致」を条件に判定されて
いるため、大会名の表記ゆれ(または日付の誤り)があるだけで実在するboutが誤って
「大会が存在しない」と判定されてしまう。相手名は大会名より表記ゆれが少なく、
より強い一致条件として使える。

具体的には、C型と判定された各行について、該当団体の**全大会・全bout(日付を問わず)**
を対戦相手名で総なめし、選手本人(slugまたは氏名一致)と相手(氏名一致)の両方が
一致するboutを探す。見つかれば「実在するboutが大会名(または日付)の表記ゆれで
誤検知されていただけ」と判定し、除外する。見つからなければ「残件」として残す。

対象は **DEEP・パンクラス・RIZINのみ**。修斗は指示書②-c/R-6〜R-8(修斗公式プロフィール
ページ経由でのbout投入、#350でマージ済み)で別トラック対応済みのため対象外。

### 結果

| | 件数 |
|---|---|
| 対象(DEEP+PANCRASE+RIZIN)C型 | 144件 |
| 相手名クロス突合で実在bout発見(誤検知として除外) | 31件(21.5%) |
| **残件** | **113件** |

誤検知率は先行調査の61%より低い(21.5%)。理由は、先行調査の36件が「その日に
該当団体の大会は実在するが大会名が別物」という高シグナルのサブグループだけを
対象にしていたのに対し、今回の144件は「その日に大会が1件も無い」サブグループ
(後述、142件中132件相当)を含んでおり、こちらは大会名表記ゆれでは説明できない
(=相手名クロス突合でも発見できない)真のカバレッジ不足が多いため。

誤検知31件の団体別内訳: DEEP 26件・PANCRASE 4件・RIZIN 1件。

### スクリプト自体の限界(調査中に発見)

相手名クロス突合の過程で、`kozaki-ren`(小崎蓮/小崎連)のケースで**選手本人側の
異体字ゆれ**(fighters.ts側は「小崎連」、deepRecords.json側は「小崎蓮」、読みは
同じ「こざきれん」)により、相手名(切嶋龍輝)は完全一致していたにもかかわらず
本人側の名前不一致でボットが検出できていなかったことが判明した。個別に
`KNOWN_NAME_VARIANTS`として補正し、上記の31件・113件は補正後の値。この種の
「相手名ではなく本人名の異体字」による見落としが他にも残っている可能性があり、
113件は下限ではなく「現状のスクリプトで検出できる誤検知を除いた残り」である
点に留意。

分類の凡例:
- **①構造的カバレッジ不足**: deepRecords.json/rizinRecords.jsonの収録開始日より前、
  または該当ブランドの収録範囲外。実在イベントの確認が取れているものはWikipedia側の
  誤りではなく団体側データの欠落。

  文字列だけで団体を誤認識したケース。真の誤検知。
- **③日付誤り(疑い)**: 近傍(同月日・±数日)に実在大会があり、Wikipedia側の
  年/日付の誤記の可能性が高い。#353で修正した13件と同型。

- **④未解決**: 上記いずれにも明確に分類できず、個別の一次資料確認が必要。

## まとめ

- 対象144件(DEEP/PANCRASE/RIZIN、修斗除く)のうち、対戦相手名クロス突合で
  **31件(21.5%)を誤検知として除外**、残件は**113件**。
- 残件113件は主にDEEP(106件、93.8%)に集中し、うち57.5%(65件)が
  2002〜2013年の団体データ収録が疎い年代に集中している。
- サンプル検証(20件)の結果、残件の内訳は大きく4種に分かれる:
  1. 団体データの収録開始日・収録ブランド範囲より前の**構造的カバレッジ不足**
     (実在イベントの確認が取れたものが複数、Wikipedia側は正しい)
  2. 大会名の文字列だけで団体を誤認識する**org誤判定**(PANCRASEで1件確認、
     真の団体はパンクラスではない海外提携興行)
  3. 年・日付の1桁〜数日のずれによる**日付誤り疑い**(#353と同型、複数件確認)
  4. 個別の一次資料確認が必要な**未解決**案件(goto-joji含む)
- RIZINの残件6件は実質**1イベント(旗揚げ戦)のみ**に起因し、団体データ側の
  収録開始日(RIZIN.1=2016-04-17)より前のため構造的に説明がつく。
- PANCRASEの残件1件は団体誤判定(真のPancrase大会ではない)。

**このPRは規模測定・分類のみで修正は行っていない。** 次のアクションとしては、
①構造的カバレッジ不足(特にDEEP 2002〜2013年、106件中65件)をどこまで追うかの
方針決定、③日付誤り疑いの個別修正(#353と同型のパターンで残り数件〜十数件の
可能性)、④未解決案件の個別一次資料確認、の3トラックに切り分けるのが妥当と考える。
