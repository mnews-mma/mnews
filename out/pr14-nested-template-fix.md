# PR-14: Wikipedia戦績パーサのネストテンプレートバグ修正

## 経緯

別セッションの調査(`out/kana-leg4-report.md`、mainツリーに未コミットのまま存在していたため、着手前に本PRの`out/pr14-reference-kana-leg4-report.md`として保存した)で、本番の`scripts/standup-pipeline/ingest_wikipedia.py`に2つのバグが発見されていた(調査側は測定のみで本番コードは未修正のまま)。

## バグの内容

1. `FIGHT_CONT_RE`(`{{Fight-cont|...}}`を検出する正規表現)が非貪欲マッチで**最初の`}}`で止まっていた**。対戦相手欄に`{{仮リンク|名前|en|英語名}}`のようなネストしたテンプレートがあると、そのテンプレート自身の閉じ`}}`で行全体が打ち切られ、決着・大会名・日付が丸ごと空になっていた。
2. `protect_wikilinks()`(フィールド分割前に`|`を保護する処理)が`[[wikilink]]`のみを対象にしており、`{{仮リンク}}`等のネストしたテンプレートを保護していなかった。

### 実例(アンディ・フグ、2000-07-07 K-1 SPIRITS 2000 戦)

修正前の正規表現でのマッチ結果:
```
'○|{{仮リンク|セドリック・マヌーフ|en|Cedric Manhoef'
```
(閉じタグを`{{仮リンク}}`自身の`}}`と誤認し、そこで切れている。決着・大会名・日付は完全に失われる)

修正後:
```
'○|{{仮リンク|セドリック・マヌーフ|en|Cedric Manhoef}}|3R 1:50 KO（右ストレート→パウンド）| LFA 213|2025年7月26日'
→ mark='○', opponent='セドリック・マヌーフ', method='3R 1:50 KO（右ストレート→パウンド）', event='LFA 213', date='2025年7月26日'
```

## 修正内容

- `{{Fight-cont|...}}`の検出を、ネストした`{{...}}`の深さを数える`find_fight_cont_blocks()`に置き換えた(非貪欲正規表現をやめ、開き`{{Fight-cont|`から対応する閉じ`}}`を深さカウントで特定)。
- `protect_wikilinks()`に、`[[wikilink]]`保護に加えて`{{template|...}}`形式のネストしたテンプレートの保護を追加(最初の引数を表示名として残す)。

## 検証

同一のwikitextキャッシュ(`raw/wp_wikitext_509.json`、508記事)に対して、修正前コード(mainのHEAD時点)と修正後コードをそれぞれ実行して直接比較した:

- 修正前(HEADのコードで再現): 5,636行(コミット済み`data/kick/bouts_wikipedia.json`と完全一致することを確認)
- 修正後: 5,701行
- **差分: 消失0件・新規追加65件**(pure superset、既存行への変更・削除は一切なし)

新規追加65件全件に検査A(ルール混入: 寝技語彙/判定なし/勝敗なし/エキシビション/ボクシング)を実施し、**該当0件**を確認。

## 適用方法

完全な再実行(`ingest_wikipedia.py`を通常どおり実行)は、無関係なWikipedia本文の自然な改稿(前回キャッシュ取得時点からの編集差分、実測で約111行)を巻き込むため、PR-10と同じ方式で**差分パッチ**を採用した: コミット済み`bouts_wikipedia.json`に、新規に判明した65行のみを追加した(既存行は一切変更しない)。

**波及チェックで発見・修正**: 追加した65行のうち2行(ジョムトーン・チュワタナ→ジョムトーン・ストライカージム、ブアカーオ・ポー.プラムック→ブアカーオ・バンチャメーク)が、統合済み選手の旧`fighter_slug`(統合前の識別子)を使っていたため、`unmatchedBoutsBaseline`のratchetガードが実際に検知した(12件→14件で停止)。統合後の現行identityに置き換えて解消した(fighter_slug複合キーの罠、既知のパターン)。
