# 読み充填レグ④ Wikipedia棚卸しのやり直し - 測定レポート

対象母集団: レグ③で確認した「記事あり(完全一致)718件」(`out/kana-leg3-wiki-existence.csv`)。PR-8.5(#546)が使っていた一覧2ページの746行ではなく、記事の実在確認に基づく母集団に差し替えて棚卸しをやり直した。

**受入条件の確認**: 残余ゼロ(全718件で検証コード上 `total == covered + missing` を確認、`fail_count: 0`)。安保瑠輝也(欠落19件)・与座優貴(欠落16件)ともに欠落あり側に出た。`fighters.json` / `bouts_wikipedia.json` の md5は開始時・終了時で不変。

## 1. 718件のフル戦績抽出

| 区分 | 件数 |
|---|---|
| `{{Fight-cont}}` テンプレートで戦績表あり | 501 |
| 汎用wikitableで戦績表あり(安全網、目視で正当性確認) | 1 |
| 戦績表なし | 216 |

汎用wikitableについては22件の候補(Fight-contなしでwikitableありの記事)のうち、勝敗マーク検出で1件のみを採用した。残り21件は目視サンプル(`ISSEI`・`TAKUYA`)で**同名の別人(ミュージシャン)の記事で、表はディスコグラフィだった**ことを確認しており、21件が同種の誤ヒットである可能性が高い(全件は未確認)。「戦績表なし」216件も同様に同名別人の誤ヒットを一定数含むとみられ、全件が実在選手の記事とは限らない。

### 抽出ロジックのバグ修正(既存 `ingest_wikipedia.py` からの流用時に発見)
既存の本番パーサをそのまま流用したところ、2つのバグを発見し本レグで修正した(本番側は未修正のまま、修正提案のみ):
1. `{{Fight-cont|...}}` を検出する正規表現が非貪欲マッチで**最初の`}}`で止まっていた**ため、対戦相手欄に`{{仮リンク|名前|en|英語名}}`のようなネストしたテンプレートがあると、そのテンプレート自身の閉じ`}}`で打ち切られ、決着・大会名・日付が丸ごと空になっていた(修正前: 15,058行中594行が空、修正後: 81行に減少)。
2. リンク保護処理が`[[wikilink]]`のみを対象にしており、`{{仮リンク}}`や`{{flagicon}}`等のネストしたテンプレートを保護していなかったため、テンプレートの引数(`en`・`JPN`等)が大会名フィールドに漏れ込んでいた。
