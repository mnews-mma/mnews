# パンクラスGate/プロ昇格トーナメント除外フィックス — 着手前に想定外の規模拡大を検知、実装せず停止

ブランチ: `investigate/ushiku-juntaro-record-display` / PR #443

## 経緯

前回報告(32bout・9イベント・実在選手3名)を前提に、指示どおり`build-pancrase-records.ts`の修正実装に着手する準備として、実装前の最終確認(「差分は32boutの削除だけであること」の検証)を行った。その過程で、**前回の32bout集計が実際にはもっと広い範囲の一部でしかなかった**ことが判明した。**コードは一切変更していない**(調査のみ、`multiOrgRecord.ts`もrevert済みのまま無変更)。

## 何が想定と違ったか

前回の32bout集計は、`<h3>`セクション見出し(「パンクラスゲート」「プロ昇格トーナメント」等)配下に**別建てで**現れるパターンだけを対象にしていた(親h3を再取得して検出)。

今回、`data/pancraseRecords.json`に現在コミットされている生データ自体を`headingText`/`weightClassRaw`/`note`に対して「プロ昇格」という文字列で直接検索したところ、**h3を介さず個々のbout見出しに直接埋め込まれているケースが56bout・8イベント**見つかった(ネットワーク取得不要、既存データの文字列検索のみ)。

両方の検出方法(h3配下+headingText直埋め込み)を合わせた対象イベントは**16イベント**(前回9イベントから拡大)。

さらに、その過程で**別種の問題**も見つかった: `パンクラスゲート2009`(2009-05-24・2009-07-26の2大会、あわせて45bout)は、**大会名自体に「パンクラスゲート」という既存フィルタの登録済みキーワードをそのまま含んでいる**にもかかわらず、現在の`data/pancraseRecords.json`に**一切除外されずそのまま残っている**。これはh3伝播の問題とは無関係で、`filter-nonpro-bouts.ts`(既存の除外バッチ)がこの2大会に対して一度も正しく適用されていない(または適用後に無フィルタで再取得・上書きされた)ことを示唆する、別種の既存ギャップ。

## 影響を受けるmnews FIGHTERS(登録済み選手)

headingText直埋め込み56boutの時点で、前回の3名(牛久絢太郎・名田英平・泰斗)に加えて**新たに2名**が該当することを確認した:

- `fujii-nobuki`(藤井伸樹): 2010-12-05 PANCRASE 2010 PASSION TOUR「プロ昇格トーナメント決勝戦」vs青山祐大(負け)
- `kubota-taito`(窪田泰斗): 2010-12-05 同大会 vs林紘之(勝ち)

→ **確定している実在選手は最低5名**(ushiku-juntaro・nada・taito-rangers・fujii-nobuki・kubota-taito)。パンクラスゲート2009(45bout)側の該当選手は未調査(下記「未実施」参照)。

## 判断: ここで停止する

指示の受入条件「差分は32boutの削除だけであること。他のboutの追加・変更・欠落が1件でも出たら、その場で止めて内訳を報告」に該当したため、実装(`build-pancrase-records.ts`修正・9イベント再取得・`data/pancraseRecords.json`反映)には着手していない。

理由:
1. 対象は32bout/9イベント/3名ではなく、少なくとも56+32(重複あり、正確な重複排除後の合計は未算出)bout・16イベント・5名以上に拡大している。
2. `パンクラスゲート2009`(45bout)は今回のh3伝播修正とは別種の既存ギャップで、対象範囲・原因ともに未調査。この2大会を含めるとさらに規模が変わる。
3. これらを合わせて1PRで全部直すか、`ushiku-juntaro`の2boutだけに絞った局所対応にするか、あるいは`パンクラスゲート2009`等の既存ギャップを別トラックとして切り出すかは、範囲の取り方そのものがユーザー判断事項であり、勝手に決めて実装を進めるべきではないと判断した。
